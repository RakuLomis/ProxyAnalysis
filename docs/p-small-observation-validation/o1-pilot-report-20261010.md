日期：2026年10月10日。

本轮在已登记的24个physical PCAP上完成了O1先导。**旧共同合格TCP范围的1235条post连接，十项统计全部精确重放；但完整端点范围新增的9条非空连接缺少初始SYN证据，使9个父访问未通过冻结的保守资格规则。**因此，计数实现与来源审计通过，24访问先导闸门未通过。全量480访问、O2独立固定窗口、冻结模型推理以及后续训练均未启动。

## 2 端点来源与权限隔离

每个部署的端点由两个自有校准访问登记：Bing搜索和MDN文档。两者均在fold0 G0对应部署的C区。准备器从proxy出口TCP元数据取服务端地址与端口，两项证据必须一致，实际四部署均登记到一个一致端点。

端点白名单在任何PCAP读取前冻结。它不包含客户本地端口、旧连接ID、配对成员表或测试socket名单。实际端点地址只保存在本地`private/`登记表及工作包，不写入公开报告或96维数值特征。本轮假定攻击者已经通过自有校准知道节点端点，没有验证未知节点自动发现。

提取工作包仅含四类字段：opaque访问token、physical路径、端点白名单及数值窗口。提取器不读取业务标签、内容ID、URL、pre特征、NetLog、CDP、trace或旧配对名单。方向定义为本地到已登记服务端为up，反向为down，不按首个载荷包猜测方向。

提取后，审计器读取这24项的旧post缓存，核对同窗口、同成员统计。额外范围归因读取的是自有训练内容的post连接元数据，每项均登记一个已有C权限角色；这些元数据没有进入工作包，也没有用于删除连接、选择端点或修改窗口。没有读取pre数值列或pre PCAP。

## 3 窗口与统计口径

O1沿用已封存原窗口的`start_ns`与`end_ns`，采用左闭右开区间。旧结束条件仍依赖浏览器quiescent事件。本轮只传入旧数值边界，没有打开NetLog重新选择窗口。

TCP生命周期判定可查看整个已批准physical文件中的包头；窗口外payload不保留，也不用于唯一字节区间、事件或游程状态。U、E和新字节游程在窗口内冷启动，不能扣掉窗口前已经出现的相同字节。

十项原始统计保持为：

| 特征 | 本轮定义 |
| --- | --- |
| W_up和W_down | 正TCP payload包的观测载荷字节总和，包含重复字节 |
| U_up和U_down | 窗口内TCP序号区间并集长度，表示观测唯一字节 |
| P_up和P_down | 正payload TCP包数 |
| E_up和E_down | 新增观测唯一字节大于零的包事件数 |
| FR_packet_runs | 正payload包方向游程数，包含重传包影响，首个非空游程计1 |
| R_unique_zero_runs | 正新字节事件的零阈值方向游程数，不替代原FR |

排序依据为整数时间戳与原始包序号。SYN和FIN的序号占用不算payload，ACK-only连接不进入非空汇聚分母。U另做独立区间边界扫描，并与增量并集和事件新字节和核对；W、P、FR另由正payload包列表复算。

96维汇聚继续使用四个字节统计的9箱和六个计数统计的10箱，每条非空连接等权，各特征分布块归一化。不按字节加权，也不加入端点、端口、标签或flow数量。失败访问不补零、不生成伪合法向量；JSON中的`x`为null，宽表缺失值不代表零。

## 4 工程核验

原37项合成测试与新增9项测试全部通过，共46项。测试包括重传、部分重叠、乱序、回绕、窗口冷启动、左右边界、端点方向、分片、截断、冲突payload、socket复用、同ISN终止后歧义、IO额度与禁止第二遍读取。

真实先导中，24文件全部完成解析，捕获解析失败、端点包截断和分片失败等全局失败访问为0。已识别端点TCP包在epoch之间的分区守恒和独立计数检查通过；这不是对全部链路层包都赋予TCP归属。原始SHA256与解析在同一顺序读取中计算，没有为哈希再扫描PCAP。

产物验证独立重放62项封存文件哈希、源码及允许的元数据来源，权限与产物完整性验收通过。**该验证的passed=true不等于先导闸门通过**；闸门记录的`O1_engineering_pilot_passed`仍为false。

## 6 同范围重放与SS的UDP差异

旧共同合格TCP范围1235条post连接，十项统计全部与新物理重建精确一致：SS 288条、Trojan 304条、VLESS 322条、VMess 321条。零缺失、零数值差异；没有依靠删连接或容差放宽获得匹配。

另一个较宽参照是旧`post-W-events.parquet`。它保留的是选定代理载体的正transport payload事件，**并非仅共同合格TCP pair**。对于SS，它还包括原生UDP。不能把旧W总事件数直接当作O1端点TCP范围应当复现的数量。

| 部署 | 旧W事件 | O1正TCP payload事件 | 旧W中未在TCP提取出现的UDP事件 | O1额外TCP事件 |
| --- | ---: | ---: | ---: | ---: |
| SS | 135202 | 20837 | 114591 | 226 |
| Trojan | 138951 | 139949 | 0 | 998 |
| VLESS | 137542 | 138358 | 0 | 816 |
| VMess | 142289 | 143237 | 0 | 948 |
| 合计 | 553984 | 442381 | 114591 | 2988 |

事后post元数据归因确认，114591条未匹配旧W事件全部属于UDP，没有未解释类型或未匹配TCP事件。因而，这个差值不是TCP丢包或重建错误；UDP本来不进入冻结的TCP十统计和96维输入。

包级守恒关系为：`553984 − 114591 + 2988 = 442381`。本轮新增的2988条TCP payload事件全部保留在提取事件中，没有因缺少旧成员关联而删去。

首版先导审计表使用`missing_old_packets`这个通用字段名，记录的是与旧W总范围不相交的事件；必须结合上述UDP归因解释，不能引用该字段宣称丢包。原表和闸门没有事后改写。即使按正确TCP范围核对，9个访问的生命周期资格问题仍然存在，先导仍不能宣布通过。

同样，SS的TCP子集不能被表述为该访问全部代理工作负载。未来跨协议对比仍须保留这一观测范围说明。

表中数值用于失败诊断，不表示这些连接已经获得完整身份资格。九条连接的首次观测相对旧窗口起点在0.120至2.167秒之间，末次观测距离窗口结束约0.396至10.134秒。时间位置不能证明它们在窗口内新建，也不能替代SYN证据。

九条连接都没有对应的旧post socket登记，且其正payload事件与旧W缓存交集为0。由此可以确认：它们不是旧共同合格TCP连接计数复现失败，而是更宽端点观测范围中此前未登记的连接。**不能仅凭“未登记”把它们认定为无关背景并删除，也不能确认它们究竟来自健康检查、提前建立的持续连接或捕获缺失。**

窗口内观测字节和游程仍可计算，但“可计算观测统计”与“完整连接epoch身份已证实”是两种资格。本轮固定规则采用后者作为访问输入门，未混用二者。

## 8 覆盖与跨访问身份边界

本轮没有建立独立固定窗口时钟锚点或连续捕获证明。24项中只有1项的首末实际包时间覆盖整个旧窗口；其余23项不满足这个包时间跨度条件。首个包相对窗口起点约为−26.710至1093.914毫秒，末包相对结束约为−1747.310至210.455毫秒。

首末包不包围窗口不自动意味着漏包，可能只是边界附近没有包；包时间包围窗口也不证明中间无丢失。本轮记录该状态，不把它升级为连续覆盖证据。旧窗口被接受仅用于明确的条件化离线诊断，O2仍不合格，丢包状态仍未知。

先导内跨访问审计未发现共享的“socket＋精确包时间＋包内容指纹”证据组，也未发现跨访问共享instance token。没有仅凭相同5-tuple、相同ISN或相同包内容判定同一连接。

这项阴性检查只覆盖24文件。九条midstream连接的完整身份仍未证实，不能据此宣布全480访问、所有训练与测试折已经排除跨flow泄露。

## 10 阶段结论与下一决策

本轮可以保留三个明确结论：

1. 取消旧成员选择后，提取器能够从已知校准端点的physical流中保留更宽连接范围，且旧共同合格TCP统计完全复现。
2. SS旧W与TCP输入的总量差异来自原生UDP范围，不是本轮TCP遗漏；完整端点范围还包含此前未登记的TCP事件。
3. 严格访问级资格对midstream连接敏感。少量身份未证实连接会使整个访问失去候选向量资格，该问题不能通过沿用旧成员名单掩盖。

本轮不支持新的分类增益、O2攻击条件已满足、完整捕获无丢失或全队列无跨flow泄露。

**当前停止在A17之前，保留全部24项，不扫描其余456项，不删九条连接，不缩短窗口，不运行F1。**下一决策应先明确midstream连接的测量资格：继续要求完整epoch身份，还是另行登记“中途观测且身份未证实”的窗口统计版本，并明确其泄露审计和使用限制。后者是观测契约修订，不是本轮已经执行的修复；需要确认后才能实施。

即使未来完成资格修订或先导问题定位，全量physical读取仍需单独确认480文件的预算。此前文件stat总量15671085556字节，约14.595 GiB；不能由本轮24文件审批自动扩展到该范围。O2时钟、起点与覆盖问题仍为独立节点。
