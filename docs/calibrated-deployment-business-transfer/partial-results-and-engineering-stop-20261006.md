### 四个部署与六类业务

本轮复用 Extend 数据的排他 TCP 连接资格集合，使用 SS、VLESS、Trojan、VMess 四个部署。不是旧0916队列，也不是64 URL 分类。

每个业务有5个内容，每个内容在每个部署有4次访问，重复编号为1、2、3、4。六类是 domain × activity：

AnyTLS 和 Hy2 不在这个同粒度主队列中。AnyTLS 不具备本轮要求的排他 TCP 对资格；Hy2 本批次缺少可用于该主口径的 W 缓存并存在 carrier 资格问题。不能把历史批次的 Hy2 排除理由自动视为本批次唯一原因。

这里的“部署”包括协议、节点、配置和路径条件，并非只改变协议名称的受控实验。当前批次 VLESS 是 TCP加TLS，不能套用旧批次 REALITY与Vision 的阶段解释。VMess 登记的 auto 配置也不能等同于已经保存精确最终安全模式。

### 十项连接统计和96维访问表示

模型输入不是 IP、端口、SNI 或域名字符串，而是合格连接统计在一次访问内部的分箱频率：

| 特征 | 含义 |
| --- | --- |
| W_up 与 W_down | 两方向正 TCP payload 字节，包括重复传输的观测负载 |
| U_up 与 U_down | 两方向观测到的唯一 TCP 字节 |
| P_up 与 P_down | 两方向正 payload 包数 |
| E_up 与 E_down | 两方向具有正唯一新字节量的事件数 |
| FR_packet_runs | 正 payload 包方向段数，非空时为1加方向切换次数 |
| R_unique_zero_runs | 唯一新字节到达过程在零阈值下的方向段数 |

前4项各9个分箱，后6项各10个分箱，合计96维。每项特征在访问内部按合格连接归一化，因此本轮不是旧七维访问总量生成器，也不是记录序列编码器实验。

FR 与唯一新字节方向段分别保存，不能把后者改名为原 FR。概率核按特征分别建模，不声称已经建立十项特征的完整联合分布。

### 内容划分与模型配置

五个全局内容折中，每折有6个内容，各业务一个。相同内容在所有部署中的两侧、重复访问和内部连接整体留出；没有随机拆分同访问内的 flow。

第一阶段的 pre 与 PostMix 模型由源训练区内部内容验证选择正则参数，不根据实际目标部署的测试表现选择来源或参数。post 矩阵复用已有 KSR1 的20个源外层模型。本轮模型均是96维输入、6类输出、没有隐藏层的多项逻辑回归，不是 MLP、SSL 或 LLM。

正式拟合和模型预测采用 Pytorch312、PyTorch 2.5.1、CUDA 12.4、RTX 4060 Ti、float64；不使用 CPU 训练回退。零初始化、LBFGS、strong Wolfe线搜索、最多500次迭代。正则为 `0.0005 × (1+t) × ||W||²`，偏置不正则化，候选 `t ∈ {0, 0.25, 1, 4}`。

本次新增的结果整理脚本仅在 CPU 上读取已保存预测、计算指标和绘图，没有新拟合，也没有执行模型推理。

## 源概率核的迁移和信息论解释

### 评分对象

本阶段复用各源部署在外层24个训练内容上拟合的核，在目标留出连接对上离线计算：

\[
L_{s\rightarrow t}=\mathbb E_t[-\log_2 M_s(b\mid a)],
\qquad
L^{\mathrm{marginal}}_{s\rightarrow t}=\mathbb E_t[-\log_2 q_s(b)].
\]

期望按访问内部连接、内容内部四次重复、内容之间依次等权。十项复合权重为前8项各1/12，FR和唯一新字节方向段各1/6。下表中的比较基准是源部署的出口边际核，不是已知目标分布的最优边际模型。

定义描述性收益 `gain = marginal loss − conditional loss`。它是固定离散核的留出对数评分差，不是直接测得的互信息或条件熵，也不是业务分类增量。测试 pre 仅在该离线评分使用，不进入分类器、校准、缩放或模型选择。

本次没有按这些结果删特征、改权重、合并分箱或选择迁移方向。主实验原预注册方案保留。

## 未完成的主实验要回答什么

主问题是：三个源部署已经提供六业务训练库，目标部署只提供四类辅助业务的配对校准，能否改善目标另两类业务在真实留出 post 上的识别？

每个外层场景使用源侧288访问、目标四类校准64访问；目标另两类训练区32访问的 pre 和 post 都禁止参与拟合、缩放、生成查询和选参。目标外层测试24访问覆盖全部六类。五折、四目标、三个固定业务组，共60个外层场景。

| 组 | 目标没有训练侧pre或post的两类业务 |
| --- | --- |
| G0 | GitHub仓库与YouTube搜索结果 |

## 隔离检查和结论边界

这些是应用层角色白名单和已登记实体审计，不是操作系统沙箱，也不是所有PCAP中完整TCP连接出生与重用的普遍证明。`universal_TCP_epoch_proof` 仍为 false，不应声称已经排除全部可能的跨捕获连接身份问题。

本次没有改动封存训练代码、模型、契约或失败状态，没有重训，没有放宽500次预算或梯度门限，也没有读取主实验测试标签或测试pre。新增脚本和整理产物与封存实验目录分开。

数据内容和部署在历史研究中已反复分析；五折内容留出属于拟合期隔离，不是外部新日期、全新节点或研究者未接触目标的盲测。没有据本阶段结果改掩码、挑业务或选更容易的目标。

## 当前结论和后续处理

可以正式保留三项阶段结论。第一，当前入口分箱统计具有较稳定的跨部署业务可预测性，但不是不变业务语义。第二，出口业务分类与源概率核的跨部署复用都存在明显方向差异，单纯增加源post部署不能解决所有目标。第三，固定核的条件对数评分收益和业务决策迁移并不同步，概率关系的存在需要另外检验其分类用途。

不能保留为成果的是精确配对校准已经提高未校准业务分类、组级控制已经更弱、三项主要比较已经通过或未通过，以及无索引单侧访问提取已经成立。这些问题在本次停止之前没有获得主实验结果。

下一步若继续，应先单独修复工程可诊断性：保存失败任务的全部质量检查数值，再在同一合法训练角色上定位停止条件及尺度问题。任何缩放规则、优化算法、预算或接受门限的改动都要登记为明确修订，并说明哪些已有模型或训练视图可以复用、哪些必须重新生成。不能删CT1、跳过失败候选，或默认只跑配对臂来绕过预定主比较。

本次仅分析整理；修复和重新启动需要另行确认。第一阶段产物不应因主实验停止而删除或覆盖。
