# 辅助业务校准迁移实验第二版中止分析

本轮运行已退出，但没有完成主实验。2026年10月6日18时34分08秒，正式内层训练的CT1候选因原坐标梯度超限而停止。60个先导候选全部合格，正式目录中共有104个不同的合格内层模型；尚未生成源内选择、外层模型、主测试预测或三项主要统计比较。

本轮支持的结论是：等价预条件化解决了原先那个失败角色，并且失败日志和接受门正常发挥作用；它尚未满足整个训练矩阵的数值求解要求。这不是漂移方法的分类负结果，也不是完成后的分类报告。

## 实验任务与比较

实验使用extend中的SS、VLESS、Trojan和VMess四个已登记部署，共30个全局内容、每部署120次访问、合计480次访问和23566条排他TCP连接对。六类业务为Bing搜索结果、MDN文档、GitHub仓库、Wikipedia文章、YouTube搜索结果、YouTube视频播放。AnyTLS和Hy2未纳入本轮排他TCP任务。

采用五折全局内容留出；同一内容在所有部署中的两侧、重复访问和内部连接保持同折。每次三个源部署提供六类业务，目标部署只有四类辅助业务提供训练pre/post，另两类目标业务的训练pre和post均禁止参与拟合。测试仅输入目标post的96维连接特征直方图。不是目标部署零校准，也不是新类别识别。

| 臂 | 额外训练视图或资源 | 所回答的问题 |
| --- | --- | --- |
| CT0 | 与主槽相同的真实源post参照，以及目标辅助业务post | 充分post监督能达到什么程度 |
| CT1 | 源pre原样进入辅助槽，不使用精确对应 | 更多源侧数据是否已经有用 |
| CT2 | 经固定CORAL变换的源post辅助视图 | 常规分布适配参照 |
| CT3 | 目标辅助业务的匿名组级核映射源pre | 粗对应能提供什么 |
| CT4 | 目标辅助业务的真实配对核映射源pre | 精确对应能否提供额外价值 |
| StrongPost | 仅通过源内验证选择CT0或CT2及正则候选 | 强post参照 |
| CT5 | 既有完整六类目标post监督模型 | 更多目标资源的额外参照 |

五主臂保持相同的资源质量规则和线性分类器。模型为96维输入、六类softmax，没有隐藏层，共582个权重和偏置参数。正则候选为t取0、0.25、1、4，rho等于0.001乘以1加t。预条件化只改变可逆优化坐标，不改变分类表示、源内选择规则、损失或偏置不正则化的约定。

## 新失败发生在哪里

失败角色为`main/f0/shadowsocks/G0/i2/vless`，臂为CT1，正则候选t等于0。角色名中的SS是外层实际目标；该源内任务以VLESS作伪校准部署，实际目标SS不进入该拟合。G0的目标未覆盖业务是GitHub仓库和YouTube搜索结果。

这不是上一轮的`i1/vless`角色，而是另一个内层内容划分。失败训练输入为336乘96，标准化后最大绝对值为336.7727，共享真实post缩放的最小尺度约0.00143961。CT1保留原样pre视图，因此pre在post坐标下可能远离post训练范围；较大的标准化值本身不能作为篡改或非法样本的依据，也不应为了训练顺利而裁剪它。

加载失败检查点并独立复算得到原梯度最大值1.4293377615989185×10⁻⁵，与日志差3.3376×10⁻¹⁵；复算目标与日志差4.1633×10⁻¹⁷。失败不是记录误差，不能因为它只比门限高约42.9%就事后接受。

## 与上一轮异常有什么不同

原先失败的`i1/vless`、CT1、t等于0，确实用满500次迭代，原梯度为0.0022676853。预条件化后该角色在380次迭代结束，原梯度为3.6127×10⁻⁶，通过，并且重复参数完全一致。

新失败却在350次提前返回，只违反原梯度门，未触发预算门。因此，不能将本次继续归因为“500次不够”，更不能认为单纯将max_iter改大就必然修复；相同的目标变化条件可能仍在350次附近结束优化。

预条件化满足Theta等于V乘以L的逆，原梯度等于V梯度乘以L转置。可逆坐标变换保持目标函数，却不保持最大坐标梯度的数值尺度。当前证据直接支持“优化器的目标变化停止条件未保证原坐标验收”，尚不支持目标公式错误、业务标签错误或整个模型不适合分类等更强结论。

## 数据封存与结论边界

本次检查通过了原13个与新8个封存Python源码、计划和契约链，以及953项历史依赖、5960个角色包、15053项复用产物登记和4个原状态快照的hash。这些清单存在重叠，不能相加后声称检查了同样数量的不同文件。失败训练slot的hash与日志一致，失败模型未发布为合格模型。

本次分析未读取测试评分包，没有新训练、优化器step、业务预测或选参。上述hash与局部数值复核不等于最终全量泄露审计通过；主流水线尚未走到最终验证。

上一阶段的部署迁移诊断仍可保留：pre跨部署六类F1的12方向平均约0.8073，post跨部署平均约0.2785；三个源部署混合post的四目标平均约0.5002。VLESS到Trojan的post F1为0.8193，反向为0.7387，而VMess到VLESS及Trojan分别只有0.0794和0.0763。这说明当前表示的部署迁移困难具有方向性，并不意味着所有不同代理都不能迁移。详表见[部署迁移诊断](F:/Program/VSCode/MyGit/ProxyAnalysis/docs/calibrated-deployment-business-transfer/migration-diagnostics.md)。这些是旧阶段已完成诊断，不是本轮新主结果，也不是带目标C校准的StrongPost成绩。

当前不能回答CT4是否优于StrongPost、CT1或CT3，不能报告本轮主比较显著性，也不能把这次工程中止解释为真实配对漂移无业务收益。104个模型的训练目标不同，训练目标的高低本身也不能用来排列方法的测试性能。

## 后续修复需要决定什么

优先修订统一的数值停止策略，使停止与原坐标梯度验收一致，而不是放宽验收、删除CT1或改业务任务。候选包括更严格的变化停止规则，或者明确使用原梯度的受控求解终止方式；哪一种能够覆盖全部角色，仍需有限数值验证，不能由这一个失败推定。

新的求解停止规则、总预算、拟合量和控制任务需要另行登记、确认后执行。五主臂必须统一适用，不只对CT1追加step。若修改优化流程，应说明104个旧候选是否全部重新拟合，以免混用未经登记的求解版本。既有run-01、run-02、失败状态和修复证据继续保留。

本次没有修改封存求解器、门限或预算，没有重启正式实验。
