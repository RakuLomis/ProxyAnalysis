# post输入关联表征残差分支实验结果分析

日期：2026年10月14日。运行：`post-input-associated-representation-20261014/run-02`。本报告对应修订批处理数值接口后的Stage A，不覆盖run-01的P1停止记录，也不改变本轮模型、损失、数据权限或资格门。

## 1 核心结论

本次源内实验已经完成，正式业务评价没有完成。运行于北京时间18:09:35停止在P3最终端点封存，原因是路径拼接代码误用了下标访问，报错`'WindowsPath' object is not subscriptable`。这不是训练预算耗尽，也不是梯度或CUDA验收失败。

在该工程错误发生之前，720个合法源内任务、10,800次残差分支拟合、720份入口教师和源内选择均已完成。60个外层角色的A1、A2、A3共180项策略决定全部选择回退P-small，启用率为0%。没有实际H预测、评分或新的主比较区间。

本轮最明确的研究结果是：在冻结P-small、修正系数0.1、weight L2系数0.01、固定1000步训练及已登记候选范围内，新增post输入关联表征分支没有达到源内启用标准。真配和组级监督均降低了训练表征误差，但未提供规定幅度的源内未覆盖业务CE改善。不能将这一结果表述为“新分支已在H上分类失败”，也不能将其推广为“任何post输入关联分支都没有价值”。

## 2 实验任务和数据权限

### 2.1 数据与任务

实验沿用Extend的四个合格TCP部署：SS、VLESS、Trojan和VMess。冻结主队列为30个内容、六类业务、每内容每部署四次重复，共480次访问、23,566个连接对。AnyTLS和Hy2没有加入本轮。

六类业务为Bing搜索结果浏览、MDN文档浏览、GitHub仓库浏览、Wikipedia文章浏览、YouTube搜索结果浏览和YouTube视频播放。三个遮蔽组分别缺少：

| 遮蔽组 | 目标部署未提供训练数据的业务 |
| --- | --- |
| G0 | GitHub仓库、YouTube搜索 |
| G1 | Bing搜索、Wikipedia文章 |
| G2 | MDN文档、YouTube视频 |

外层角色为四目标部署×五全局内容折×三个遮蔽组，共60个。同一内容的全部部署、重复、两侧流量及内部连接整体划分，未将一个父访问的flow拆入不同集合。

每外层角色允许使用三源库的288次配对访问和目标C的64次配对访问。目标U训练区32次访问的任一侧均禁止读取；目标H为24次留出访问，只有全部模型端点封存后才允许post推理，预测封存后才允许读取标签。每外层角色有12个合法源内伪目标任务，总计720个。

### 2.2 数值输入和表示

输入仍为原96维访问直方图，包含上下行W、U、P、E、FR_packet_runs和R_unique_zero_runs十个块。没有增加IP、端口、SNI、域名文本、协议ID、连接数或身份索引等模型输入。

入口教师为`96→16 ReLU→8线性瓶颈→6分类头`，共1742个参数。关联监督使用八维连续瓶颈，而非六类logit、概率或one-hot。教师拟合后冻结，并使用合法训练pre的加权均值和标准差固定目标坐标。

post分支为`96→16 ReLU→8`，与原96维post拼接后经`104→6`残差头。新增2318个参数，原P-small的582个参数始终冻结。预测为：

\[
\ell(x)=\ell_{P\text{-small}}(x)+0.1P_6\{V[x,G(x)]+c\}.
\]

残差最后一层零初始化，因此训练起点与P-small精确一致；训练和推理的修正头均接收估计的`G(post)`，不在训练时用真实pre表征替代它。

### 2.3 实验臂与损失

| 臂 | 新增监督 | 本轮作用 |
| --- | --- | --- |
| A0 | 无新增训练 | 冻结P-small |
| A1 | CE，无入口表征目标 | 同容量纯post适配控制 |
| A2 | 同内容、同部署的四次pre瓶颈均值 | 组级对应监督 |
| A3 | 同次访问的pre瓶颈 | 精确关联监督 |

各新增臂使用相同P-small分类槽、标签、质量、尺度、架构和更新预算。该共享基座本身已利用原精确配对；A2是新增表征监督的组级控制，不是整个系统从未使用真实关联。

固定损失为原训练槽的带权CE、可选真实post上的表征MSE和新增网络weight L2。真实MSE不施加在CORAL或mapped-pre合成视图上。外层共有928个带权计算行、352次真实训练访问；内层分别为480个计算行和192次真实训练访问，不能将计算行数当作新增采集量。

固定Adam学习率0.001、1000步全批训练、分支梯度范数clip=5、weight L2=0.01、bias不惩罚。A1的λ=0；A2/A3的λ∈{0,0.1,1}，其中λ=0精确复用A1，既不额外拟合也不读取关联目标。三个残差seed为20261014、20261015、20261016。

### 3.2 精确停止位置

`eval/post_input_associated_representation_v3/final_train.py`第34行使用了：

```python
ROOT[e['base_path']]
```

`ROOT`是WindowsPath，不能用这种下标方式拼接文件路径；残差路径分支存在同样写法。路径应使用`ROOT / e['base_path']`等Path拼接操作。

错误发生在写出`manifests/endpoints.json`之后、生成`models-complete.json`之前。因此端点列表存在不等于最终模型已经封存。后续H推理依赖该封存门，本轮没有跨过它。

本次分析没有修改这段代码、没有重启运行、没有回写停止状态。需要修复的是端点封存接口，不是重新训练720个源内任务；源内全部回退的决定也不会因修复路径而改变。

## 4 源内启用结果

### 4.1 冻结资格门

每候选以12个合法源内任务和三个seed评价，四个内层内容折先合并，再对三个伪目标部署及seed等权汇总。必须同时满足：

1. 未覆盖业务CE相对同任务P-small至少下降0.002 nats。
2. 未覆盖业务F1不下降。
3. C总体F1下降不超过1个百分点。
4. 各伪目标部署的C F1下降不超过2个百分点。

没有合格候选时，该角色、方法、全部seed精确回退P-small。H结果不能用于决定回退。

## 5 预测变化与训练表征

### 5.1 新分支很少改变分类决策

每个非等价配置共有51,840条源内任务预测，包括三个seed、不同遮蔽及重叠伪目标任务。下表是预测暴露计数，不是51,840次独立访问，不能据此做普通样本显著性检验。

| 配置 | 类别改变 | 修复原错误 | 新增错误 | 两者都错但类别改变 | 平均概率总变差 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A1，λ=0 | 0 | 0 | 0 | 0 | 0.0003262 |
| A2，λ=0.1 | 0 | 0 | 0 | 0 | 0.0003572 |
| A2，λ=1 | 14 | 5 | 3 | 6 | 0.0007110 |
| A3，λ=0.1 | 3 | 0 | 3 | 0 | 0.0003703 |
| A3，λ=1 | 25 | 14 | 8 | 3 | 0.0007492 |

概率总变差定义为六类概率与基座概率的绝对差之和的一半。概率确实变化了，新分支不是完全没有参与计算；但平均变化约为0.0003–0.00075，绝大多数预测没有跨越分类边界。

三个seed的A3、λ=1分别改变9、8、8次类别，修复5、5、4次错误，新增3、2、3次错误。A1和A2、λ=0.1在每个seed都没有类别改变。零F1变化不意味着概率严格相同，概率层的微小变化仍能使CE上升。

### 5.2 入口教师没有全常数坍缩

720份教师的训练准确率均值为99.7092%，中位数100%，最小96.3542%。八维瓶颈的有效秩均值3.5001，范围2.2994–4.3045；5760个原始坐标标准差的最小值为1.0682，未发生全部瓶颈坐标近常数的停止条件。

这些诊断说明教师提供了非退化、可拟合训练标签的目标。它们不是教师未见内容泛化结果，也不证明目标C能够覆盖U所需的联合表征关系。高训练准确率不能当作迁移能力的证据。

训练表征MSE和总目标均下降，说明不能简单归因为“网络完全没有训练”。更大的λ使训练MSE更低，但对应源内留出CE的平均上升更明显。恢复目标改善并没有自动变成未覆盖业务判别改善。

A2与A3的目标方差不同，A2是四次重复均值，其MSE不能直接与A3比较后宣布组级恢复更好；以上数值仅用于各配置自身训练过程的描述。它们也不是留出post的恢复误差或覆盖率。

## 6 独立核验与结果边界

本次独立分析重新计算了全部420条候选资格记录，包括λ=0别名。CE、F1_U、F1_C和最差伪目标C代价的最大数值差为0，资格布尔值全部一致。候选及决策封存哈希、源内预测哈希、720个合法源内标签包哈希均通过核对。

源内训练与选择阶段的读取日志没有`H-predict`或`H-score`目的。本分析仅读取允许的源内标签及冻结预测、训练诊断、合同和基座资产，没有读取实际目标U、H-pre或H标签，没有新增任何拟合。

已写出的720条端点均为无残差的基座引用。每个角色的四臂、三个seed共12条端点均引用同一份P-small，60份基座模型的来源哈希核对通过。这是未封存列表的结构与来源核验，不代替P3正式封存。

若按冻结回退策略完成封存和接口重放，四臂将是同一post函数的精确别名。届时新策略间增量为构造上的零，不是“小样本区间跨零证明统计等效”。原P-small历史F1_U为0.796931，不能将其重新标记成已经执行的本轮H评分；本轮没有新增H成绩。

因此，当前不能报告新的A3−A0、A3−A1、A3−A2内容簇区间，不能填入本轮H上的CE/Brier、逐业务提升、C代价或错误翻转。源内任务彼此重叠，三个seed也不是独立内容；本报告不以这些计数重造业务显著性。

## 7 研究判断与建议

### 7.1 本轮已经回答的问题

将关联监督放入一个训练和推理都读取post的非线性分支，在架构和工程上已经可以执行。修订后的批处理数值接口通过了固定门限，完整源内训练没有因CUDA或预算停止。入口目标非全常数，训练MSE下降，估计分支也确实改变了概率。

但在当前冻结候选中，这些变化没有达到源内业务启用要求，同容量纯post分支同样没有获得资格。不能把负向结果唯一归因于“关联模块未参与推理”，因为本轮候选本来就在推理计算中保留了它；也不能说真配相对容量或组级控制已经获得增量。

### 7.2 工程结项不需要重跑训练

建议只做一次独立登记的端点封存修复：保留本次停止记录和P2全部产物，修正Path拼接接口，复核源内决策、基座引用及代码来源，然后封存720个逻辑端点。不得改λ、损失、资格门或回退决定，不重新拟合基座或残差。

在全部回退的情况下，可按合同完成精确别名及post-only接口的结项核验；若仍执行H预测与评分，也只能是封存后的固定基座重放，不是为了寻找未获资格分支的H分数。无需再投入一次约五小时源内训练。

本次用户请求为结果分析，尚未实施上述修复或重放。

### 7.3 暂不进入Stage B

没有源内合格候选，也没有独立证据将当前失败定位为任务相关条件多模态模糊。仅凭MSE下降或教师训练准确率高，不足以开启条件GAN。应保留P-small、接受当前固定Stage A候选未获启用资格的结果，先完成工程结项，不自动增加模型、搜索尺度或放宽CE门。

这不否定训练关联的全部用途。此前P-small已有业务收益，其身份归因边界继续保留；本次只限制“冻结P-small后，当前连续入口教师＋小型残差分支”这一具体新增方法。
