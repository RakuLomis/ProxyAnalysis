## 已验证的训练侧定位

不新增拟合、只读取训练数据及已有损失记录的 `numerical_audit.py` 完成了15组核对：

- post数值矩阵及训练业务标签顺序一致；
- E/H初始化哈希一致；
- 训练采样表哈希一致；
- post预处理缩放器一致。

第一步损失均一致，但两次半权重CE与一次CE的初始最大梯度差为1.862645149230957e−9。15组中14组在前1000步已有超过1e−6的损失偏离；最早发生于第257步，前1000步最大损失差约0.005243212。

此外，旧B0L在第二阶段只以三个独立模型构成参数batch继续训练，新实现继续使用24个独立模型的参数batch。这里的3与24是并行模型数，不是访问batch；访问batch仍为120，模型之间没有共享参数。

**解释边界：**已观察到不相同的浮点梯度累加和后续损失轨迹，也确认了继续阶段的计算路径不同。这使数值路径敏感性成为具体候选解释，但本次零新增拟合审计没有独立分解两者的贡献，不能把全部最终偏差确定归因于某一个原因，更不能把它写成协议机制效应。

## 推荐修复和需要确认的动作

推荐保持J1至J7、全部数据、损失数学定义、步数、温度、权重、统计家族和1e−5门限不变，仅修复J0的计算路径：

1. 对J0将两份相同CE的等权和化简为原单CE实现，使用旧显式正则求和路径，避免重复分支的梯度累加差异。
2. 前1000步匹配旧24独立模型的计算布局；后1000步匹配旧三个B0L模型的继续布局，并重置Adam状态。
3. 先在训练侧对照损失与中间权重，证明实现路径复现，不根据测试正确率调实现。
4. 仅为五折三seed的15个J0作2000步修复重拟合，保留第一次拟合及失败门记录。
5. 以独立修复文件及清楚的版本来源生成新的预测封存；不能静默改写原封存文件。
6. 数值门通过后再执行固定评分、六项内容bootstrap、独立指标核验和正式报告；未通过则继续停止，不改变容差。

这是数学目标不变的实现修复建议，但会使实际正式长度的训练执行次数从120增加到135，其中15次是J0修复重拟合。最终主比较仍应使用预定120个模型，旧15个J0明确作为失败实现记录，不择优。追加执行成本应透明登记，不隐称预算未增加。

由于计划要求预算变化先确认，本次未执行15个追加拟合，未用旧B0L直接替换J0，未评分。需要用户确认这一额外数值修复步骤。
