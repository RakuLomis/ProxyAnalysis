# 0916 VLESS记录表示：错误定位与冻结编码器诊断总结

## 1. 完成情况与核心判断

2026-09-26完成计划中的两阶段：现有预测错误定位，以及75个冻结flow编码器读出任务。旧S/L实验、模型、预处理及成员未更改；没有重新扫描PCAP或重训SSL。新任务只训练原65→32→6小分类头。

核心更新是：**真实配对预训练得到的冻结表示具有业务可读性，也优于同内容跨重复错配，但低于post-only和双侧侧内SSL控制。因此，“没有额外配对收益”不宜简化成“没有学到任何有用信息”，也不支持把问题全部归因于微调破坏了一份原本最优的表示。**

S2继续作为冻结的强直接post监督基线，本轮不据结果扩模型、换损失或搜索训练参数。

## 2. 研究范围与固定配置

- 当前0916 VLESS部署：120访问、30内容、六个domain×activity业务，每内容四次重复，1179共同合格排他TCP pair。
- 原五折未见内容划分，每折训练96访问、测试24访问；同内容重复、父访问内flow及两侧不跨集合。
- 三seed：20260918、20260919、20260920。
- 保留R静态记录结构与独立新字节时间线；原训练post预处理；不额外标准化冻结embedding。
- flow编码器32维输出，访问聚合mean/max与log1p(flow_count)，得到65维输入。
- 编码器冻结：structure、temporal、sproj、tproj、fusion；不用SSL projector或旧分类头。
- 五个来源Q0随机初始化、Q1–Q4分别为L1–L4的第1000步SSL结束检查点。
- 相同fold/seed下五来源新头初值、批次顺序及训练预算相同；每任务1000步、batch24、Adam lr=0.001、CE(nats)+weight L2(1e−4/2)，bias不正则。
- 编码、训练、测试全在RTX4060Ti CUDA，float32、确定性算法，无AMP/TF32、无早停、无测试调参。
- 75任务共75000个小头更新；1800条OOF行仍只对应120独立访问。任务内部计时合计146.60秒，含提取与小头训练等任务内工作，不等于完整流水线墙钟耗时。

这是小型非线性冻结探针，不是线性探针，也不是旧157维统计特征分类实验。

### 支持什么解释

1. 所有SSL来源均优于匹配随机编码器，说明在固定低容量读出下，预训练确实形成了可利用结构；不宜说本轮所有SSL都没用。
2. 真实配对优于局部错配，但未超过post-only和侧内控制。其优势是相对于当前错配机制的有限优势，不是相对于一般SSL的额外业务收益。
3. Q3在SSL结束时已经低于Q1/Q2，不符合“真配先形成最强表示，之后统一微调才抹去优势”的简单解释。
4. Q3约0.790而其旧L3微调约0.947；Q4约0.696而旧L4约0.955。标签微调提升了二者的实际性能，冻结阶段的真/错配差没有保留为旧最终分类优势。这里只是两训练条件的描述比较，不是对微调因果机制的识别。
5. S2直接监督约0.972仍是当前最强基线。冻结读出和端到端训练的参数权限不同，不能把S2直接混入冻结探针排名后声称一种信息量上界。

### 仍不能确定什么

结果不能定位唯一失败原因；不能排除固定优化、embedding尺度、正则或有限读出容量的影响；不能证明任何非线性读出都无法利用某种信息。当前L4的跨重复flow rank对应也不保证相同资源语义，Q3−Q4不是纯访问噪声比例或互信息。
